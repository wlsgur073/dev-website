# 라우팅 시스템

## 개요

Vue Router 4를 사용하여 SPA 라우팅을 구현합니다. 동적 import를 통한 코드 분할과 네비게이션 가드를 통한 접근 제어가 적용되어 있습니다.

## 라우트 구조

### 공개 라우트 (Public Routes)

인증 없이 접근 가능한 페이지들입니다.

| 경로 | 컴포넌트 | 레이아웃 | 설명 |
|------|---------|---------|------|
| `/` | HomePage | DefaultLayout | 메인 랜딩 페이지 |
| `/docs` | DocsIndexPage | DocsLayout | 문서 인덱스 |
| `/docs/:slug` | DocsSlugPage | DocsLayout | 문서 상세 |
| `/api` | ApiDocsPage | DefaultLayout | API 문서 |
| `/releases` | ReleasesPage | DefaultLayout | 릴리스 목록 |
| `/releases/:id` | ReleaseDetailPage | DefaultLayout | 릴리스 상세 |
| `/announcements` | AnnouncementsPage | DefaultLayout | 공지사항 목록 |
| `/announcements/:id` | AnnouncementDetailPage | DefaultLayout | 공지사항 상세 |
| `/pricing` | PricingPage | DefaultLayout | 가격 정책 |
| `/community` | CommunityPage | DefaultLayout | 커뮤니티 |
| `/search` | SearchPage | DefaultLayout | 검색 |

### 인증 라우트 (Auth Routes)

`guest: true` 메타 속성이 설정되어 있어 인증된 사용자가 접근 시 `/console`로 리다이렉트됩니다.

| 경로 | 컴포넌트 | 레이아웃 | 설명 |
|------|---------|---------|------|
| `/login` | LoginPage | AuthLayout | 로그인 |
| `/register` | RegisterPage | AuthLayout | 회원가입 |

### 보호된 라우트 (Protected Routes)

`requiresAuth: true` 메타 속성이 설정되어 있어 인증이 필요합니다.

| 경로 | 컴포넌트 | 레이아웃 | 설명 |
|------|---------|---------|------|
| `/console` | ConsolePage | ConsoleLayout | 대시보드 |
| `/console/api-keys` | ConsoleApiKeysPage | ConsoleLayout | API 키 관리 |
| `/console/billing` | ConsoleBillingPage | ConsoleLayout | 결제 관리 |

### 관리자 라우트 (Admin Routes)

`requiresAuth: true`와 `requiresAdmin: true` 메타 속성이 모두 설정됩니다.

| 경로 | 컴포넌트 | 레이아웃 | 설명 |
|------|---------|---------|------|
| `/admin/announcements` | AdminAnnouncementsPage | ConsoleLayout | 공지사항 관리 |
| `/admin/releases` | AdminReleasesPage | ConsoleLayout | 릴리스 관리 |

### 에러 라우트

| 경로 | 컴포넌트 | 설명 |
|------|---------|------|
| `/403` | ForbiddenPage | 권한 없음 |
| `/:pathMatch(.*)` | NotFoundPage | 404 에러 |

## 라우트 메타 속성

```typescript
interface RouteMeta {
  title?: string        // 페이지 제목
  requiresAuth?: boolean // 인증 필요 여부
  requiresAdmin?: boolean // 관리자 권한 필요 여부
  guest?: boolean       // 게스트 전용 (인증 시 리다이렉트)
}
```

## 네비게이션 가드

### 전역 가드 (beforeEach)

```mermaid
flowchart TD
    A[라우트 변경 시작] --> B{첫 로드인가?}
    B -->|예| C[authStore.initAuth 실행]
    B -->|아니오| D{guest 라우트인가?}
    C --> D
    D -->|예| E{인증되었는가?}
    E -->|예| F[/console로 리다이렉트]
    E -->|아니오| G[진행]
    D -->|아니오| H{requiresAuth인가?}
    H -->|예| I{인증되었는가?}
    I -->|아니오| J[/login으로 리다이렉트]
    I -->|예| K{requiresAdmin인가?}
    K -->|예| L{관리자인가?}
    L -->|아니오| M[/403으로 리다이렉트]
    L -->|예| N[진행]
    K -->|아니오| N
    H -->|아니오| G
    G --> O[라우트 변경 완료]
    N --> O
```

### 가드 동작 흐름

1. **앱 첫 로드 시**: `authStore.initAuth()` 호출하여 토큰 갱신 시도
2. **게스트 전용 라우트** (`/login`, `/register`):
   - 이미 인증된 사용자 → `/console`로 리다이렉트
3. **보호된 라우트** (`/console/*`):
   - 미인증 사용자 → `/login`으로 리다이렉트 (redirect 쿼리 파라미터 포함)
4. **관리자 라우트** (`/admin/*`):
   - 일반 사용자 → `/403`으로 리다이렉트

### 페이지 제목 업데이트 (afterEach)

라우트 변경 후 `document.title`을 동적으로 업데이트합니다.

```typescript
router.afterEach((to) => {
  const title = to.meta.title
    ? `${to.meta.title} | DevAPI`
    : 'DevAPI'
  document.title = title
})
```

## 코드 분할 (Code Splitting)

동적 import를 사용하여 각 페이지를 별도 청크로 분리합니다.

```typescript
// 예시: 홈 페이지
{
  path: '/',
  component: () => import('@/pages/HomePage.vue')
}
```

### 번들 분할 결과

| 청크 | 포함 컴포넌트 |
|------|-------------|
| `HomePage.[hash].js` | HomePage |
| `LoginPage.[hash].js` | LoginPage |
| `ConsolePage.[hash].js` | ConsolePage |
| ... | ... |

## 프로그래매틱 네비게이션

### 라우터 인스턴스 사용

```typescript
import { useRouter } from 'vue-router'

const router = useRouter()

// 페이지 이동
router.push('/console')

// 쿼리 파라미터와 함께
router.push({
  path: '/login',
  query: { redirect: '/console/api-keys' }
})

// 뒤로 가기
router.back()

// 현재 경로 교체 (히스토리에 추가하지 않음)
router.replace('/home')
```

### 라우트 정보 접근

```typescript
import { useRoute } from 'vue-router'

const route = useRoute()

// 현재 경로
console.log(route.path)        // '/docs/quickstart'

// 동적 파라미터
console.log(route.params.slug) // 'quickstart'

// 쿼리 파라미터
console.log(route.query.page)  // '2'
```
